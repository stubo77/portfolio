Systems · 2024

Distributed KV Store

A Raft-based key-value store written in Rust with linearizable reads, snapshot-based log compaction, and a clean HTTP API.

Timeline 3 months
Role Solo project
Stack Rust, Tokio, gRPC
Status Open source

Problem

Existing embedded KV libraries offered great single-node performance but lacked built-in replication. I wanted a small, understandable implementation that I could use as a learning substrate for distributed systems concepts.

Approach

I implemented the Raft consensus algorithm from scratch in Rust using Tokio for async I/O. The design separates the consensus layer from the state machine, making it straightforward to swap storage backends.

  • Leader election with randomized election timeouts
  • Log replication with batched AppendEntries RPCs
  • Snapshot transfer for lagging followers
  • Linearizable reads via ReadIndex

Challenges

The hardest part was correctly handling log truncation during snapshot installation while simultaneously processing incoming RPCs. Rust's ownership model actually helped here — the compiler caught several subtle aliasing bugs at compile time.

Results

The cluster sustains ~40k writes/sec on commodity hardware with 3 nodes and p99 latency under 4ms on a local network. The codebase is ~6k lines of Rust with thorough property-based tests using proptest.

Learnings

Reading the original Raft paper alongside Raft's TLA+ spec was essential. Writing the implementation forced me to understand every edge case the spec glosses over in prose.
